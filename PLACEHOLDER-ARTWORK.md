# Placeholder artwork

Every image in `public/placeholders/` is **original illustration generated by
this repository** — see `tools/artwork/`. Nothing is sourced from the web, no
third party's photography is used, and no other manufacturer's branding
appears anywhere in the set.

That matters for a client demo: putting a competitor's product photography on
a FireOxine-branded site is a copyright and passing-off exposure, and stock
photographs of fifteen different extinguishers shot in fifteen different rooms
look like a catalogue nobody finished.

## What is drawn

| | Count | Size | Used by |
|---|---|---|---|
| Product renders | 15 | 1200 × 1200 | `ProductImage.url` |
| Collection banners | 12 | 1600 × 1000 | `Category.imageUrl` |

Each render is drawn to the proportions of a real stored-pressure unit and is
**colour-coded to its actual extinguishing medium** — cream band for ABC dry
powder, yellow for AFFF foam, blue for water, pale blue for mist, green for
clean agent, amber for wet chemical, slate for Class D — with the correct
discharge device for the type: a flared horn on CO2, an applicator lance on
wet chemical and Class D, a hose elsewhere. The class letters on each label
match the product's actual `ProductFireClass` rows.

## Regenerating

```bash
node tools/artwork/build.mjs     # SVG sources -> tools/artwork/svg
node tools/artwork/pages.mjs     # wrap each in an HTML page with the real fonts
# then rasterise the pages to public/placeholders/*.jpg
```

Rasterising uses headless Chrome so the Anton and Archivo faces render rather
than falling back. The SVG sources are the artwork of record; the JPEGs are
build output.

## Replacing them

These exist to be thrown away.

```bash
npm run placeholders:off   # strip the set; the designed "photograph pending"
                           # plates take over, which is also a valid look
npm run placeholders:on    # put them back
```

Uploading a real photograph through `/admin` replaces the placeholder for that
product immediately — placeholders live under `/placeholders/` and client
uploads under `/uploads/`, so the two never collide and the demo set can be
removed in one operation without touching anything real.
